From Wikipedia, the free encyclopedia

Syntactic entity in a programming language with a determinable value

In [computer science](/wiki/Computer_science "Computer science"), an **expression** is a [syntactic](/wiki/Syntax_(programming_languages) "Syntax (programming languages)") entity in a [programming language](/wiki/Programming_language "Programming language") that may be evaluated to determine its [value](/wiki/Value_(computer_science) "Value (computer science)") of a specific semantic [type](/wiki/Data_type "Data type").[[1]](#cite_note-Mitchell2002-1)[[2]](#cite_note-GabbrielliMartini2010-2) It is a combination of one or more [constants](/wiki/Constant_(programming) "Constant (programming)"), [variables](/wiki/Variable_(programming) "Variable (programming)"), [functions](/wiki/Function_(programming) "Function (programming)"), and [operators](/wiki/Operator_(programming) "Operator (programming)") that the programming language interprets (according to its particular [rules of precedence](/wiki/Order_of_operations "Order of operations") and of [association](/wiki/Associative_property "Associative property")) and computes to produce ("to return", in a [stateful](/wiki/State_(computer_science) "State (computer science)") environment) another value.
In simple settings, the [resulting value](/wiki/Return_type "Return type") is usually one of various [primitive types](/wiki/Primitive_data_type "Primitive data type"), such as [string](/wiki/String_(computer_science) "String (computer science)"), [boolean](/wiki/Boolean_expression "Boolean expression"), or numerical (such as [integer](/wiki/Integer_(computer_science) "Integer (computer science)"), [floating-point](/wiki/Floating-point_number "Floating-point number"), or [complex](/wiki/Complex_data_type "Complex data type")).

Expressions are often contrasted with [statements](/wiki/Statement_(computer_science) "Statement (computer science)")—[syntactic](/wiki/Syntactic "Syntactic") entities that have no value (an instruction).

Definition
----------

[[edit](/w/index.php?title=Expression_(computer_science)&action=edit&section=1 "Edit section: Definition")]

Like in mathematics, an expression is used to denote a value to be evaluated for a specific value type supported by a [programming language](/wiki/Programming_language "Programming language"). In some cases an expression can't be fully evaluated; in this case, the value is [undefined](/wiki/Undefined_value "Undefined value"), even though the calculation was effected and finished.[[1]](#cite_note-Mitchell2002-1): 26

The process of evaluating an expression to a [well-defined](/wiki/Well-defined "Well-defined") value type is called *[evaluation](/w/index.php?title=Evaluation_(programming_language)&action=edit&redlink=1 "Evaluation (programming language) (page does not exist)")*; it can occur in different contexts, such as definition and initialization [*[needs independent confirmation](/wiki/Wikipedia:Verifiability#Sources_that_are_usually_not_reliable "Wikipedia:Verifiability")*].

Examples
--------

[[edit](/w/index.php?title=Expression_(computer_science)&action=edit&section=2 "Edit section: Examples")]

`2 + 3` is both an [arithmetic](/wiki/Arithmetic_expression "Arithmetic expression") and programming expression, which evaluates to `5`. A variable is an expression because it denotes a value in [memory](/wiki/Memory_(computer) "Memory (computer)"), so `y + 6` is also an expression. An example of a [relational expression](/wiki/Relational_operator "Relational operator") is `4 ≠ 4`, which evaluates to `false`.[[3]](#cite_note-3)[[4]](#cite_note-4)

### C

[[edit](/w/index.php?title=Expression_(computer_science)&action=edit&section=3 "Edit section: C")]

You can see how the parts of the code can be an expression.

```
int main(void) {

    int y = 10; // The expression "y = 10";
    int x = 40; // The expression "x = 40";
    
    int result = x + y; // The expression "result = x + y" is evaluated;

    return 0; // When a function is called, its return expression is evaluated and the call expression yields that value to the caller.
}
```

In [C](/wiki/C_(programming_language) "C (programming language)") (and many other [programming languages](/wiki/Programming_languages "Programming languages")), the *["="](/wiki/Equals_sign "Equals sign")* is considered an [operator](/wiki/Operator_(computer_programming) "Operator (computer programming)") [like in mathematics](/wiki/Operator_(mathematics) "Operator (mathematics)"); more specifically, a [binary operator](/wiki/Binary_operation "Binary operation").

Void as a result type
---------------------

[[edit](/w/index.php?title=Expression_(computer_science)&action=edit&section=4 "Edit section: Void as a result type")]

In [C](/wiki/C_(programming_language) "C (programming language)") and most C-derived languages, a call to a function with a [void](/wiki/Void_type "Void type") return type is a valid expression, of type void.[[5]](#cite_note-5)
Values of type void cannot be used, so the value of such an expression is always thrown away.

Side effects and elimination
----------------------------

[[edit](/w/index.php?title=Expression_(computer_science)&action=edit&section=5 "Edit section: Side effects and elimination")]

In many programming languages, a function, and hence an expression containing a function, may have [side effects](/wiki/Side_effect_(computer_science) "Side effect (computer science)"). An expression with side effects does not normally have the property of [referential transparency](/wiki/Referential_transparency "Referential transparency"). In many languages (e.g. [C++](/wiki/C%2B%2B "C++")), expressions may be ended with a semicolon (`;`) to turn the expression into an expression [statement](/wiki/Statement_(programming) "Statement (programming)"). This asks the implementation to evaluate the expression for its side-effects only and to disregard the result of the expression (e.g. `x+1;`) unless it is a part of an expression statement that induces side-effects (e.g. `y=x+1;` or `func1(func2());`).

### Caveats

[[edit](/w/index.php?title=Expression_(computer_science)&action=edit&section=6 "Edit section: Caveats")]

The formal notion of a side effect is a change to the abstract state of the running program.

Another class of side effects are changes to the concrete state of the computational system, such as loading data into [cache memories](/wiki/Cache_memory "Cache memory"). Languages that are often described as "side effect–free" will generally still have concrete side effects that can be exploited, for example, in [side-channel attacks](/wiki/Side-channel_attack "Side-channel attack").

Furthermore, the elapsed time evaluating an expression (even one with no other apparent side effects), is sometimes essential to the correct operation of a system, as behaviour in time is easily visible from outside the evaluation environment by other parts of the system with which it interacts, and might even be regarded as the *primary* effect such as when performing [benchmark testing](/wiki/Benchmark_(computing) "Benchmark (computing)").

It depends on the particular programming language specification whether an expression with no abstract side effects can [legally be eliminated](/wiki/Program_optimization "Program optimization") from the execution path by the processing environment in which the expression is evaluated.
