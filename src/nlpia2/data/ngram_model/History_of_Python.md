History of the Python programming language

[![](//upload.wikimedia.org/wikipedia/commons/thumb/7/72/Python_logo_1990s.svg/250px-Python_logo_1990s.svg.png)](/wiki/File:Python_logo_1990s.svg)

Old Python logo, 1990s–2006

[![](//upload.wikimedia.org/wikipedia/commons/thumb/f/f8/Python_logo_and_wordmark.svg/250px-Python_logo_and_wordmark.svg.png)](/wiki/File:Python_logo_and_wordmark.svg)

New Python logo, 2006–present

[![](//upload.wikimedia.org/wikipedia/commons/thumb/d/da/Guido-portrait-2014.jpg/250px-Guido-portrait-2014.jpg)](/wiki/File:Guido-portrait-2014.jpg)

Guido van Rossum in 2014

The [programming language](/wiki/Programming_language "Programming language") [Python](/wiki/Python_(programming_language) "Python (programming language)") was conceived in the late 1980s,[[1]](#cite_note-venners-interview-pt-1-1) and its implementation was started in December 1989[[2]](#cite_note-timeline-of-python-2) by [Guido van Rossum](/wiki/Guido_van_Rossum "Guido van Rossum") at [CWI](/wiki/Centrum_Wiskunde_%26_Informatica "Centrum Wiskunde & Informatica") in [the Netherlands](/wiki/The_Netherlands "The Netherlands") as a successor to [ABC](/wiki/ABC_(programming_language) "ABC (programming language)") capable of [exception handling](/wiki/Exception_handling "Exception handling") and interfacing with the [Amoeba operating system](/wiki/Amoeba_(operating_system) "Amoeba (operating system)").[[3]](#cite_note-faq-created-3) Van Rossum was Python's principal author and had a central role in deciding the direction of Python (as reflected in the title given to him by the Python community, [*Benevolent Dictator for Life* (BDFL)](/wiki/Benevolent_dictator_for_life "Benevolent dictator for life")[[4]](#cite_note-4)[[5]](#cite_note-5)) until stepping down as leader on July 12, 2018.[[6]](#cite_note-6) Python was named after the [BBC TV](/wiki/BBC_TV "BBC TV") show *[Monty Python's Flying Circus](/wiki/Monty_Python%27s_Flying_Circus "Monty Python's Flying Circus")*.[[7]](#cite_note-7)

Python 2.0 was released on October 16, 2000, with many major new features, such as [list comprehensions](/wiki/List_comprehension "List comprehension"), [cycle-detecting](/wiki/Cycle_detection "Cycle detection") [garbage collector](/wiki/Garbage_collection_(computer_science) "Garbage collection (computer science)"), [reference counting](/wiki/Reference_counting "Reference counting"), [memory management](/wiki/Memory_management "Memory management") and support for [Unicode](/wiki/Unicode "Unicode"), along with a change to the development process itself, with a shift to a more transparent and community-backed process.[[8]](#cite_note-newin-2.0-8)

Python 3.0, a major, backwards-incompatible release, was released on December 3, 2008[[9]](#cite_note-3.0-release-9) after a long period of testing. Many of its major features were also [backported](/wiki/Backport "Backport") to the backwards-compatible Python versions 2.6 and 2.7[[10]](#cite_note-pep-3000-10) until support for Python 2 finally ceased at the beginning of 2020. Releases of Python 3 up through 3.12 include the `2to3` utility, which automates the translation of Python 2 code to Python 3.[[11]](#cite_note-11)

As of February 2026[[update]](https://en.wikipedia.org/w/index.php?title=History_of_Python&action=edit), Python 3.14.3 is the latest stable release. This version currently receives full bug-fix and security updates, while Python 3.13—released in October 2024—will continue to receive bug-fixes until October 2026, and after that will only receive security fixes until its end-of-life in 2029. Python 3.10 is the oldest supported branch of Python (albeit in the 'security support' phase).[[12]](#cite_note-12)[[13]](#cite_note-13)

Early history
-------------

[[edit](/w/index.php?title=History_of_Python&action=edit&section=1 "Edit section: Early history")]

Van Rossum first published the code (for Python version 0.9.1) to alt.sources in February 1991.[[14]](#cite_note-14)[[15]](#cite_note-15) Several features of the language were already present at this stage, among them [classes with inheritance](/wiki/Inheritance_(object-oriented_programming) "Inheritance (object-oriented programming)"), exception handling, functions, and various core [datatypes](/wiki/Datatypes "Datatypes") such as `list`, `dict`, and `str`. The initial release also contained a [module system](/wiki/Module_system "Module system") borrowed from [Modula-3](/wiki/Modula-3 "Modula-3"); Van Rossum describes the module as "one of Python's major programming units".[[1]](#cite_note-venners-interview-pt-1-1) Python's exception model also resembled Modula-3's, with the addition of an `else` clause.[[3]](#cite_note-faq-created-3) In 1994 [comp.lang.python](news://comp.lang.python), the primary [discussion forum](/wiki/Discussion_forum "Discussion forum") for Python, was formed.[[1]](#cite_note-venners-interview-pt-1-1)

Version 1
---------

[[edit](/w/index.php?title=History_of_Python&action=edit&section=2 "Edit section: Version 1")]

Python reached version 1.0 in January 1994. The major new features included in this release were the functional programming tools `lambda`, `map`, `filter` and `reduce`. Van Rossum stated that "Python acquired lambda, reduce(), filter() and map(), courtesy of a [Lisp](/wiki/Lisp_(programming_language) "Lisp (programming language)") hacker who missed them and submitted working [patches](/wiki/Patch_(computing) "Patch (computing)")".[[16]](#cite_note-16)

The last version released while Van Rossum was at CWI was Python 1.2. In 1995, Van Rossum continued his work on Python at the [Corporation for National Research Initiatives](/wiki/Corporation_for_National_Research_Initiatives "Corporation for National Research Initiatives") (CNRI) in [Reston, Virginia](/wiki/Reston,_Virginia "Reston, Virginia") from where he released several versions.

By version 1.4, Python had acquired several new features. Notable among these are the Modula-3 inspired [keyword arguments](/wiki/Keyword_argument "Keyword argument") (which are also similar to [Common Lisp](/wiki/Common_Lisp "Common Lisp")'s keyword arguments) and built-in support for [complex numbers](/wiki/Complex_number "Complex number"). Also included is a basic form of [data hiding](/wiki/Data_hiding "Data hiding") by [name mangling](/wiki/Name_mangling "Name mangling"), though this is easily bypassed.[[17]](#cite_note-17)

During Van Rossum's stay at CNRI, he launched the Computer Programming for Everybody (CP4E) initiative, intending to make programming more accessible to more people, with a basic "literacy" in programming languages, similar to the basic English literacy and mathematics skills required by most employers. Python served a central role in this: because of its focus on clean syntax, it was already suitable, and CP4E's goals bore similarities to its predecessor, ABC. The project was funded by [DARPA](/wiki/DARPA "DARPA").[[18]](#cite_note-18) As of 2007[[update]](https://en.wikipedia.org/w/index.php?title=History_of_Python&action=edit), the CP4E project is inactive, and while Python attempts to be easily learnable and not too arcane in its syntax and semantics, outreach to non-programmers is not an active concern.[[19]](#cite_note-19)

### BeOpen

[[edit](/w/index.php?title=History_of_Python&action=edit&section=3 "Edit section: BeOpen")]

In 2000, the Python core development team moved to BeOpen.com[[20]](#cite_note-20) to form the BeOpen PythonLabs team.[[21]](#cite_note-21)[[22]](#cite_note-22) CNRI requested that a version 1.6 be released, summarizing Python's development up to the point at which the development team left CNRI. Consequently, the release schedules for 1.6 and 2.0 had a significant amount of overlap.[[8]](#cite_note-newin-2.0-8) Python 2.0 was the only release from BeOpen.com. After Python 2.0 was released by BeOpen.com, Guido van Rossum and the other PythonLabs developers joined [Digital Creations](/wiki/Zope "Zope").

The Python 1.6 release included a new CNRI license that was substantially longer than the CWI license that had been used for earlier releases. The new license included a clause stating that the license was governed by the [laws](/wiki/Law "Law") of the [State of Virginia](/wiki/State_of_Virginia "State of Virginia"). The [Free Software Foundation](/wiki/Free_Software_Foundation "Free Software Foundation") argued that the choice-of-law clause was incompatible with the [GNU General Public License](/wiki/GNU_General_Public_License "GNU General Public License"). BeOpen, CNRI and the FSF negotiated a change to Python's [free-software license](/wiki/Free-software_license "Free-software license") that would make it GPL-compatible. Python 1.6.1 is essentially the same as Python 1.6, with a few minor bug fixes, and with the new GPL-compatible license.[[23]](#cite_note-lib-history-23)

Version 2
---------

[[edit](/w/index.php?title=History_of_Python&action=edit&section=4 "Edit section: Version 2")]

Python 2.0, released October 2000,[[8]](#cite_note-newin-2.0-8) introduced [list comprehensions](/wiki/List_comprehension "List comprehension"), a feature borrowed from the [functional programming](/wiki/Functional_programming "Functional programming") languages [SETL](/wiki/SETL "SETL") and [Haskell](/wiki/Haskell "Haskell"). Python's syntax for this construct is very similar to Haskell's, apart from Haskell's preference for [punctuation](/wiki/Punctuation "Punctuation") characters and Python's preference for alphabetic keywords. Python 2.0 also introduced a garbage collector able to collect reference cycles.[[8]](#cite_note-newin-2.0-8)

Python 2.1 was close to Python 1.6.1, as well as Python 2.0. Its license was renamed [Python Software Foundation License](/wiki/Python_Software_Foundation_License "Python Software Foundation License"). All code, documentation and specifications added, from the time of Python 2.1's alpha release on, is owned by the [Python Software Foundation](/wiki/Python_Software_Foundation "Python Software Foundation") (PSF), a [nonprofit organization](/wiki/Nonprofit_organization "Nonprofit organization") formed in 2001, modeled after the [Apache Software Foundation](/wiki/Apache_Software_Foundation "Apache Software Foundation").[[23]](#cite_note-lib-history-23) The release included a change to the language specification to support nested scopes, like other [statically scoped](/wiki/Static_scoping "Static scoping") languages.[[24]](#cite_note-pep-0227-24) (The feature was turned off by default, and not required, until Python 2.2.)

Python 2.2 was released in December 2001;[[25]](#cite_note-25) a major innovation was the unification of Python's types (types written in [C](/wiki/C_(programming_language) "C (programming language)")) and classes (types written in Python) into one hierarchy. This single unification made Python's object model purely and consistently object oriented.[[26]](#cite_note-26) Also added were [generators](/wiki/Generator_(computer_science) "Generator (computer science)") which were inspired by [Icon](/wiki/Icon_(programming_language) "Icon (programming language)").[[27]](#cite_note-pep-0255-27)

[![A falling weight labelled "16 ton"](//upload.wikimedia.org/wikipedia/commons/f/f7/Python_Macintosh_icon_1997%E2%80%932001.png)](/wiki/File:Python_Macintosh_icon_1997%E2%80%932001.png)

[![A highly abstracted symbol suggestive of the head ends of two snakes in a double helix viewed head-on, curved clockwise toward the viewer: a blue snake comes in from behind to the left, with head folding back on its body at the top, and a yellow snake comes in from behind to the right and its head folds back on its body at the bottom; the overall silhouette of the symbol forms a rough plus sign, and the eye locations are suggestive of a yin and yang.](//upload.wikimedia.org/wikipedia/commons/thumb/c/c3/Python-logo-notext.svg/60px-Python-logo-notext.svg.png)](/wiki/File:Python-logo-notext.svg)

Historic Python logos used on Windows (left) and the Macintosh (center), and the logo used since version 2.5 (right).

Python 2.5 was released in September 2006[[28]](#cite_note-28) and introduced the `with` statement, which encloses a code block within a context manager (for example, acquiring a [lock](/wiki/Lock_(computer_science) "Lock (computer science)") before the block of code is run and releasing the lock afterwards, or opening a [file](/wiki/Computer_file "Computer file") and then closing it), allowing [resource acquisition is initialization](/wiki/Resource_acquisition_is_initialization "Resource acquisition is initialization") (RAII)-like behavior and replacing a common try/finally idiom.[[29]](#cite_note-29)

Python 2.6 was released to coincide with Python 3.0, and included some features from that release, as well as a "warnings" mode that highlighted the use of features that were removed in Python 3.0.[[30]](#cite_note-pep-0361-30)[[10]](#cite_note-pep-3000-10) Similarly, Python 2.7 coincided with and included features from Python 3.1,[[31]](#cite_note-31) which was released on June 26, 2009.
Parallel 2.x and 3.x releases then ceased, and Python 2.7 was the last release in the 2.x series.[[32]](#cite_note-pep-0404-32) In November 2014, it was announced that Python 2.7 would be supported until 2020, but users were encouraged to move to Python 3 as soon as possible.[[33]](#cite_note-33) Python 2.7 support ended on January 1, 2020, along with [code freeze](/wiki/Code_freeze "Code freeze") of 2.7 development branch. A final release, 2.7.18, occurred on April 20, 2020, and included fixes for critical bugs and release blockers.[[34]](#cite_note-34) This marked the [end-of-life](/wiki/End-of-life_product "End-of-life product") of Python 2.[[35]](#cite_note-pep-0373-35)

Version 3
---------

[[edit](/w/index.php?title=History_of_Python&action=edit&section=5 "Edit section: Version 3")]

"Python 3" redirects here. For the Israeli missile, see [Python (missile) § Python-3](/wiki/Python_(missile)#Python-3 "Python (missile)").

Python 3.0 (also called "Python 3000" or "Py3K") was released on December 3, 2008.[[9]](#cite_note-3.0-release-9) It was designed to rectify fundamental design flaws in the language – the changes required could not be implemented while retaining full backwards compatibility with the 2.x series, which necessitated a new major version number. The guiding principle of Python 3 was: "reduce feature duplication by removing old ways of doing things".[[36]](#cite_note-36)

Python 3.0 was developed with the same philosophy as in prior versions. However, as Python had accumulated new and redundant ways to program the same task, Python 3.0 had an emphasis on removing duplicative constructs and modules, in keeping with the [Zen of Python](/wiki/Zen_of_Python "Zen of Python"): "There should be one— and preferably only one —obvious way to do it".

Nonetheless, Python 3.0 remained a [multi-paradigm language](/wiki/Multi-paradigm_programming_language "Multi-paradigm programming language"). Coders could still follow [object-oriented](/wiki/Object-oriented_programming "Object-oriented programming"), [structured](/wiki/Structured_programming "Structured programming"), and [functional](/wiki/Functional_programming "Functional programming") programming paradigms, among others, but within such broad choices, the details were intended to be more obvious in Python 3.0 than they were in Python 2.x.

### Compatibility

[[edit](/w/index.php?title=History_of_Python&action=edit&section=6 "Edit section: Compatibility")]

Python 3.0 broke backward compatibility, and much Python 2 code does not run unmodified on Python 3.[[37]](#cite_note-37) Python's [dynamic typing](/wiki/Dynamic_typing "Dynamic typing") combined with the plans to change the semantics of certain methods of dictionaries, for example, made perfect [mechanical translation](/wiki/Source-to-source_compiler "Source-to-source compiler") from Python 2.x to Python 3.0 very difficult. A tool called "`2to3`" does the parts of translation that can be done automatically. At this, `2to3` appeared to be fairly successful, though an early review noted that there were aspects of translation that such a tool would never be able to handle.[[38]](#cite_note-38) Prior to the roll-out of Python 3, projects requiring compatibility with both the 2.x and 3.x series were recommended to have one source (for the 2.x series), and produce releases for the Python 3.x platform using `2to3`. Edits to the Python 3.x code were discouraged for so long as the code needed to run on Python 2.x.[[10]](#cite_note-pep-3000-10) This is no longer recommended; as of 2012 the preferred approach was to create a single code base that can run under both Python 2 and 3 using compatibility modules.[[39]](#cite_note-39)

### Features

[[edit](/w/index.php?title=History_of_Python&action=edit&section=7 "Edit section: Features")]

Some of the major changes included for Python 3.0 were:

* Changing `print` so that it is a [built-in function](/wiki/Intrinsic_function "Intrinsic function"), not a statement. This made it easier to change a module to use a different print function, as well as making the syntax more regular. In Python 2.6 and 2.7 `print()` is available as a built-in but is masked by the print statement syntax, which can be disabled by entering `from __future__ import print_function` at the top of the file[[40]](#cite_note-pep-3105-40)
* Removal of the Python 2 `input` function, and the renaming of the `raw_input` function to `input`. Python 3's `input` function behaves like Python 2's `raw_input` function, in that the input is always returned as a string rather than being evaluated as an expression
* Moving `reduce` (but not `map` or `filter`) out of the built-in namespace and into `functools` (the rationale being code that uses `reduce` is less readable than code that uses a for loop and accumulator variable)[[41]](#cite_note-41)[[42]](#cite_note-42)
* Adding support for optional function annotations that can be used for [informal type declarations](/wiki/Gradual_typing "Gradual typing") or other purposes[[43]](#cite_note-pep-3107-43)
* Unifying the `str` and `unicode` types into `str`, representing text, and introducing a separate immutable `bytes` type; and a mostly corresponding mutable `bytearray` type, both of which represent arrays of [bytes](/wiki/Byte "Byte")[[44]](#cite_note-pep-3137-44)
* Removing backward-compatibility features, including old-style classes, string exceptions, and implicit relative imports
* A change in [integer division](/wiki/Integer_division "Integer division") functionality: in Python 2, integer division always returns an integer. For example `5 / 2` is `2`; whereas in Python 3, `5 / 2` is `2.5`. (In both Python 2 – 2.2 onwards – and Python 3, a separate operator exists to provide the old behavior: `5 // 2` is `2`)
* Allowing non-ASCII letters to be used in identifiers,[[45]](#cite_note-45) such as in `smörgåsbord`
* Unifying integer types `int` and `long` into one integer type: `int`. Python 2 `int` limits integers between `-2147483648` and `2147483647` inclusive. Any integers outside or inside this range have an `L` or `l` suffix such as `-100000000000000L`, `0l`[[46]](#cite_note-46)

### Subsequent releases

[[edit](/w/index.php?title=History_of_Python&action=edit&section=8 "Edit section: Subsequent releases")]

Python 3.2 defined a stable [ABI](/wiki/Application_Binary_Interface "Application Binary Interface"), allowing extension modules to rely on functions across different Python versions.

Python 3.5 added the typing module, which allows for [type hints](/wiki/Type_hint "Type hint") and [function signature](/wiki/Function_signature "Function signature") annotation. It additionally added the [async/await](/wiki/Async/await "Async/await") syntax. Furthermore, `.pyo` files were removed, with `.pyc` files representing both unoptimized and optimized [bytecode](/wiki/Bytecode "Bytecode").

Python 3.6 followed with async [generators](/wiki/Generator_(computer_programming) "Generator (computer programming)") and async comprehensions ([for lists](/wiki/List_comprehension "List comprehension") as well as dicts and sets), as well as formatted [string literals](/wiki/String_literal "String literal") (f-strings).[[47]](#cite_note-47)

Python 3.10 introduced [structural pattern matching](/wiki/Structural_pattern_matching "Structural pattern matching") via match/case statements. Additionally it provided improved error messages which "were inspired by previous work in the PyPy interpreter" and added the `|` [union type](/wiki/Union_type "Union type") operator.[[48]](#cite_note-48)

Python 3.11 expanded [exception handling](/wiki/Exception_handling_(programming) "Exception handling (programming)") functionality. Around this version, there has been a focus on making Python faster; 3.11 is claimed to be 10–60% faster than 3.10,[[49]](#cite_note-49) and 3.12 increases by an additional 5%.

Python 3.12 added the new keyword `type` and improved error messages.

Python 3.13 added an experimental [just-in-time (JIT) compiler](/wiki/Just-in-time_compilation "Just-in-time compilation"), the ability to disable the [global interpreter lock](/wiki/Global_interpreter_lock "Global interpreter lock"), a new and improved interactive interpreter ([REPL](/wiki/Read%E2%80%93eval%E2%80%93print_loop "Read–eval–print loop")), and an incremental [garbage collector](/wiki/Garbage_collection_(computer_science) "Garbage collection (computer science)").[[50]](#cite_note-50) Starting with Python 3.13, it and later versions receive two years of full support (increased from one and a half years), followed by three years of security support; this is the same total duration of support as previously.

Python 3.14 introduced a new tail-calling interpreter as an opt-in feature, offering 3-5% better performance.[[51]](#cite_note-51)

Python 3.15 will "Make [UTF-8](/wiki/UTF-8 "UTF-8") mode default";[[52]](#cite_note-52) This mode is supported in all current Python versions, but it currently must be opted into. UTF-8 is already used by default on [Windows](/wiki/Microsoft_Windows "Microsoft Windows") (and other [operating systems](/wiki/Operating_system "Operating system")) for most purposes, but an exception is opening files. Enabling UTF-8 also makes code fully [cross-platform](/wiki/Cross-platform_software "Cross-platform software").

#### Security

[[edit](/w/index.php?title=History_of_Python&action=edit&section=9 "Edit section: Security")]

Security updates were expedited in 2021 and again twice in 2022. More issues were fixed in 2023 and in September 2024 (for Python versions 3.8.20 through 3.12.6)—all versions (including 2.7)[[53]](#cite_note-53) had been insecure because of issues leading to possible [remote code execution](/wiki/Remote_code_execution "Remote code execution")[[54]](#cite_note-54) and [web-cache poisoning](/wiki/Cache_poisoning "Cache poisoning").[[55]](#cite_note-55)
